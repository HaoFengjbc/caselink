# PDF 案情整理页改版：一张表、少交互（2026-10-09）

## 问题

上传 PDF 后的整理页由 `MaterialReview` 与 `MaterialDateReview` 组成：每条要点一个卡片和“编辑”按钮、每个存疑日期一张核对表单、每处冲突一个必填说明框，最后还要勾 3 个确认框。信息分散，交互点多，用户反馈“难看、点不完”。

## 改动

- **一张整理表**（`AdaptiveStatement.tsx`）：材料要点并入第 ③ 步的案情表，按“当事人与背景 / 经过 / 指控与主张 / 程序与现状 / 手上材料 / 缺少的材料”分栏，每条带页码标签（多份 PDF 时为“材料1 第 3 页”）。鼠标移上去看原文；点击后可改写、改用原文或删除，改写在点“完成”时才写入。国家与法域只在“基本情况”显示，悬停可见出处。
- **日期由系统处理**（`extract.ts`、`dates.ts`）：模型给出的日期只有在引文里能核对上（等价完整日期，或原文逐字出现的“2026年10月”一类写法）才保留；否则不写日期，该条直接显示文件原文，不再生成 `dateReview`。依赖这个日期的冲突说明改为中性表述，缺口列表中提到它的条目也去掉。旧草稿中尚未处理的 `dateReview` 在最终确认时按“未知”保留。
- **记载不一致**：“采用说法 1 / 采用说法 2 / 两者都保留”一键选择，可重新选择；不选也能提交，确认时记为“两种说法都保留，待核实”。增量上传自动发现的冲突使用固定说明，两边原文在下方并列显示。
- **收尾只剩两项**（`integration.ts`）：一句话目标（4 个快捷选项）与公开边界（3 个选项，上传材料时必选，沿用 `contracts.ts` 已有规则）；具体披露限制可选。删除 3 个确认勾选框，`goalConfirmed`、`disclosureConfirmed` 由最终确认写入。“最新进展”仍作为补充问题保留，确认不会替用户勾掉。
- **其他**：隐私设置缩成一行，其余收进“更多设置”（`PrivacyPreferences.tsx`）；每份文件一行，写明页数和无法读取或未处理的页（`MaterialFiles.tsx`）；上传流程的步骤名与说明文字改成上传材料的说法。
- 修复：目标输入框原本失焦即收起，下方选项随之上移，鼠标点击会落空；现在输入框位置固定。
