# PDF 整理 30 秒超时修复（2026-10-09）

用户在正式站收到“材料整理超时，未采用整理结果；可重试或手动填写”。该文案只能来自 `extractMaterials` 的模型等待定时器，区别于文件读取 15 秒、旧总请求 55 秒及旧浏览器 60 秒的提示。PDF 原先复用了 `readIntakeConfig`，因此模型等待最多 30 秒。首次真实验收的两份短 PDF 已耗时 27,018 ms，没有足够余量。正式部署日志中也有一次 `kind=material/errorCode=TIMEOUT`；没有读取、保存或记录用户上传内容，不能凭该日志判断用户材料的具体复杂度。

## 修复

- PDF 使用独立 `AI_MATERIAL_TIMEOUT_MS`，默认和允许上限均为 120,000 ms；沿用 `OPENAI_INTAKE_MODEL` 与服务端密钥。手动描述仍保持原有 30 秒。
- 总请求 180 秒、浏览器 185 秒、Next/Vercel 路由 240 秒；上传读取和每个 PDF 解析仍各限 15 秒。保留页数、字节、文本量和输出 token 上限。
- 正在整理时提示可能需要 2 分钟并保留取消；超时提示写明实际模型等待秒数。没有自动重试，也不采用不完整结果。
- 将材料模型阶段记录包在完整的超时/取消竞态之外，保证在返回超时前已经记录模型尝试。旧日志可能因为 SDK 中止稍晚而误记 `before_model` 和空 stages，不能据此断言未调用模型或没有费用；此次修复保留失败 token/费用未知状态。
- 未更换模型，未修改当前生产已采用的直接 AI 调用策略，未触碰主工作区其他未提交工作。

平台设置依据：[Vercel 函数执行时限](https://vercel.com/docs/functions/configuring-functions/duration) 与本地安装的 Next.js `maxDuration` 文档。网站总时限保留处理、清理和错误响应的余量，并不采用模型 API 自身上限。

## 验证

- 定向服务端及手动流程：55 项通过。
- 模拟 75 秒模型响应可以接受，期间只调用一次 transport；模拟 120 秒无响应会中止并记录模型失败；主动取消仍生效。
- 构建、TypeScript 检查通过。
- 8 项浏览器测试通过，含浏览器时钟推进 75 秒后仍接收结果，取消、重试、移除、核对及原有手工流程。正式域名 15/15 免费 HTTP 检查及 2 项真实 PDF 解析/浏览器测试均通过。

本次修复验收使用虚构 PDF、模拟延时与不调用 AI 的正式 HTTP 检查，不新增真实付费模型请求。以前的真实提取证据见 `production-release.md`；此次不把模拟慢响应描述为真实 AI 验收，也尚未重试用户的原始材料。
