# 联网研究优先 · v3.1

本说明对应2026-10-09已发布实现，`PROMPT_VERSION=3.1`；旧版本结果会被标记过期，正式语料版本仍为 `2026-10-08.v2`。本轮已完成生产构建、真实模型样本及浏览器流程验收；实际范围、失败发现和剩余限制见 [verification.md](verification.md)。

实时最终分析以类似公共案件的联网研究为主、正式历史库补充。案情整理使用 GPT-6 Luna；语义规划、网页研究和综合分析使用配置的 Sol 模型（示例为 GPT-6.1 Sol）及现有服务端密钥，不需要额外搜索供应商密钥。模型可用性仍取决于实际 API 项目。

## 数据流

1. **确认输入与主目标。** 使用者核对案情并明确提交最终分析。自由目标默认就是主要诉求；旧记录中已确认的 `unknown + 非空 goalText` 被规范为 `other`，已有明确预设目标继续受到尊重。原提交输入仍用于结果身份计算。
2. **无工具语义规划。** `research/planner.ts` 将完整案情、回答、已确认笔记及目标交给无搜索工具的模型，抽象双方关系、被争议的行为、所述损害、希望获得的改变、证据问题、排除议题和未知项。自然语言字段保留具体争议含义，不把游戏服务、交易或其他民事纠纷强行归成新闻表达或刑事程序。规划最多25秒，只请求一次。
3. **校验公共研究计划。** `research/plan.ts`核对支持原话，检查常见身份标识、网址、精确金额日期、长段原文和部分矛盾。私有标识列表与核对摘录不进入搜索载荷或客户端 JSON；只保留经筛查的公共抽象。地区从当前输入规范化，英国辖区单独处理，未知或冲突地区不能直接成为原文搜索词。规划失败、筛查失败或没有可用议题时不启动搜索，也不转而挖掘原始文字的关键词。
4. **每轮分为发现与读取。** `research/provider.ts`先执行发现请求：使用原生 `web_search`，最多3次工具调用、1000 token，只产生潜在相关来源的简短说明；服务器从实际返回并可绑定引用的来源中挑选最多3个 URL。然后另发读取请求：最多3次工具调用、3500 token，要求以 `open_page` 打开这些候选页面并阅读相关正文直至结尾。发现与读取共用同一轮65秒截止时间，合计最多6次工具调用，不是各自65秒。发现阶段即使曾打开网页，其摘要也不会升级成正式研究段落；最终只保留读取阶段的报告消息。两阶段都只接收规范化地区和抽象研究计划，不接收完整案情、私有标识列表或核对摘录。优先当前争议领域的判决、法院或官方争议处理资料；人权组织资料仅用于相关问题。工具返回实际查询时另行记录，不把计划关键词冒充执行记录。
5. **引用必须匹配本轮读取。** 新实时 provider 要求所用 URL 属于选定候选，且在本轮读取阶段存在对应的 `completed open_page`。仅出现在发现结果、读取时替代搜索摘要或尚未完成的打开操作中，都不足以进入最终资料。服务器继续区分 `url_annotation` 原生 `url_citation` 注解与 `tool_returned_link` 窄回退；后者须为报告段落中的 Markdown 链接，并精确匹配本次完成工具返回的 URL，两类引用都须通过读取条件。一个段落若同时依赖已读与未通过读取匹配的引用，整段丢弃，不保留一条已读引用来支撑混合内容。未匹配的自写网址、裸 URL 和独立链接清单不能成为报告来源。服务器按 URL 分配来源 ID、绑定段落并保留 `citationKind`。同一页面可以分别支撑一审、二审等不同程序阶段的段落，允许重复引用相同来源，不要求人为寻找另一个 URL。页面明确上诉结果但没有精确日期时，应保留结果，只把日期标为未知。符合读取条件的来源标记 `pageOpened=true`；它仅表示工具完成了打开步骤，不证明完整正文已被准确理解、所有程序均已提取或段落逐句得到支持。链接仍须通过公开形态 HTTP(S) 校验，不保证页面可信，也不是任意 URL 的服务器抓取入口。
6. **无工具综合分析。** 综合模型接收完整已确认案情、研究报告和最多3个正式库候选，以严格结构输出最多5个网页案例比较、最多3个库内比较及最多3项行动。它没有搜索工具，不能把原始案情继续用于工具查询。服务器核对引用 ID、案件归属、目标、披露约束及部分法律结果表述。
7. **必要时仅补查一轮。** 若首轮搜索完成或无可用引用，而综合结果没有采用相关网页案例，且总预算至少剩余95秒，服务复用已校验计划，改从基础关系、诉求、因果、估值或证据角度再执行一轮发现与读取，然后综合。不会再次调用规划模型，不自动进行第三轮。成功后报告与分析整体替换；失败则保留此前有效配对并披露补查未完成，避免把旧行动引用绑定到新报告的同名 ID。两轮都未选到相关案例时保留资料和明确缺口，不用不相关案件填满名额。

## 资料取得、相关性与行动来源

`webResearch.status`描述资料获取：`completed`有可用引用段落，`no_results`搜索执行但没有可用引用材料，`unavailable`规划或研究未完成。取得引用不能自动证明相关性。

`researchAssessment`另列 `relevant_cases_found`、`no_relevant_cases`、`search_unavailable` 或 `not_searched`，以及尝试次数和补充研究结果。已选比较仍是 AI 对材料的判断，不是独立人工事实核查。“本次未找到”不等于不存在类似案例。

`actionOrigins`逐项标记 `ai`、`rule` 或 `preset`。真正未知的目标若被固定澄清模板处理，对应行动为 `rule`；整体 `live_ai` 只说明综合模型完成并通过校验，不能据此把规则行动标为模型生成。网页依据的行动另用 `basisType=web_research`，并在 `actionWebSources` 中记录实际引用。

结果默认打开“联网发现”，展示研究状态、时间、研究关键词、可用的工具实际查询、案例资料时点、相同点和差异；每项比较和行动紧邻引用，并区分原生引用注解与工具返回链接；来源的 `pageOpened` 记录打开步骤，不充当完整性或准确性评级。日期无来源时显示待核实。可展开研究计划、两轮记录和完整带引用段落。没有合适案例比较时仍可阅读实际检索到的资料。正式库比较单独作为补充，保留报告页码和原文。Markdown 下载与复制保留研究计划、关键词、查询、轮次、资料、比较、行动引用和来源标记。

规划或搜索不可用时，综合分析可使用已有正式库与一般准备，但会明确披露未完成网页研究。如果首轮综合模型也失败，则返回分析错误，不冒充成功。第二轮失败可以返回首轮已经通过校验的结果并说明原因。规则参考与预置演示不联网、不调用模型。

## 运行预算与请求边界

| 阶段 | 最大时限 | 输出与工具预算 |
|---|---:|---|
| Luna 案情整理，单独请求 | 30秒默认；允许1—30秒 | 4000 token；无搜索工具 |
| Sol 公共研究规划 | 25秒 | 3500 token；无工具；一次 |
| 每轮发现阶段 | 与读取共享65秒 | 1000 token；最多3次工具调用；选择最多3个来源 URL |
| 每轮读取阶段 | 与发现共享65秒 | 3500 token；最多3次工具调用；须有本阶段完成的 `open_page` |
| 单轮网页研究合计 | 65秒，不因阶段切换重置 | 工具调用合计≤6；至多两轮研究 |
| 每轮综合分析 | 90秒默认；允许1—90秒 | 9000 token默认；无工具；至多两轮 |
| 最终分析完整编排 | 270秒共享预算 | 不能因补查重新获得完整预算 |
| `/api/analyze` / 浏览器 | 300秒 / 290秒 | 平台实际时限仍须部署验证 |

整理入口 `/api/intake` 的 Route Handler 声明40秒，前端等待35秒。两个 POST 请求体上限均为512 KiB，并执行同源、JSON类型及输入契约检查，响应为 `no-store`。无站内密码；未实现跨实例持久化限流或服务端共享幂等缓存。

所有 SDK 请求设置 `store:false` 和 `maxRetries:0`。应用最多一次补充研究与 SDK 自动重试是不同机制。取消会停止后续步骤、隔离晚到响应，但不能保证已开始的上游工作不计费。多阶段及工具调用增加成本，不承诺固定费用、时延或国家覆盖。

## 隐私与法律边界

完整案情会发送给 OpenAI 的无工具规划和综合分析；首次整理也会在使用者明确同意提交后发送相关输入。公开搜索接收抽象后的研究计划，而不是原始案情。抽象与模式筛查只能降低泄露风险，不能证明完全匿名；模型可能遗漏未识别的标识、误解否定或组合出可识别信息。`store:false`也不等于供应商绝不保留数据。没有共享案情缓存或自动正式入库流程。

原生注解只提供工具标注的引用关联；`tool_returned_link`仅有段落链接与本次工具 URL 清单的精确匹配。新 provider 额外要求本轮读取阶段完成打开，仍不能证明页面主文完整可见、模型理解准确或程序摘要没有遗漏。`pageOpened`以及两类引用都不等于被引网页支持所有叙述细节，也不是逐句事实核实。模型仍可能误读来源、漏掉上诉、误判相关性或生成不充分类比，必须检查原页面与差异。历史结局不预示本案结果；产品不提供法定期限、胜诉概率、机构受理承诺或结果保证。网页与用户文字都按不可信资料处理，不能覆盖系统指令；有限校验不能证明消除了所有提示注入或法律错误。
