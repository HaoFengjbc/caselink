## Public protocol v1 (reuse existing fact schema)

1. `NewCaseInput` remains the complete fact record, including intake. `UsePreferences` is separate: `{aiEnabled,saveMode:'memory'|'local',refreshRecovery,expiresAt}`. Defaults are memory, no recovery, no expiry until opt-in. Preferences must not enter the case fact identity or erase/truncate facts. Legacy persisted records remain accessible with clear explanation; no silent deletion.
2. `DomainAssessment`: `{status:'in_scope'|'out_of_scope'|'needs_clarification',reason,clarification:string|null,resourceIds:string[]}`. B implements/export `assessDomain(input)` in `src/lib/research/domain.ts`. Server is authoritative; A displays assessment and uses it to route/clarify.
3. `CanonicalJurisdiction`: `{countryCode,country,jurisdictionCode,legalSystem,recognized}`. ISO country values and jurisdiction enum live in workflow-contracts. B exports `resolveJurisdiction(input)` from `src/lib/jurisdiction.ts`; A and intake/questions reuse it. Structured confirmed values win; a changed non-GB country cannot inherit a UK jurisdiction. Preserve source text in input.
4. `/api/analyze` accepts `AnalysisRequest`: `{input,requestId,inputVersion,operation:'initial'|'supplement',parentAnalysisId?,forceRule?,locale?,preferences?}`. Every new input version or explicit supplement uses a new request ID; unchanged retries use the same ID/version. Server binds ID to session plus canonical input hash, operation and parent; collisions with different content reject. Failure is not cached forever. Rules remain available. Default is one round; no hidden second round. Supplement means new explicit user intent, not automatic retry.
5. Error response: `{code,message,requestId,retryable?,retryAfterSeconds?,domain?}`. Codes in workflow-contracts include scope, usage-control-unavailable, concurrency, in-progress and idempotency-conflict. A aligns with B on retry behavior. Do not claim strict query control with an autonomously rewriting built-in search. If no controlled provider/Redis exists, fail closed for the affected paid/search capability with usable rule/corpus fallback and honest configuration status.
6. `SourceDescriptor` separates category (`curated_case`, `international_standard`, `mechanism`, `assistance`, `public_web`) from review status (`unreviewed`, `agent_checked`, `team_verified`, `legacy_recorded`, `conflict`), includes applicability, locator, agent/team checked dates and unknowns. New resources use the optional enriched ResourceSchema fields; C fills them explicitly. Agent checked is never team verified.
7. `AnalysisResult` adds optional `domain`, `jurisdiction`, `execution`, `snapshot` for backward compatibility. `ReportSnapshot` freezes cases/evidence/documents/resources/webResearch/sourceDescriptors, locale and version. New server results must get a generation-time snapshot; lead wires A's helper into B service at integration. A exports `captureReportSnapshot(result,locale?)`, `captureCaseSnapshot(caseIds,locale?)`, `snapshotForResult(result)` from `src/lib/reports/snapshot.ts`. Legacy missing fields stay missing and are labeled, never populated from today's corpus. Snapshot views must not re-localize against mutable current translations.
8. `ComparisonBrief` carries ID/title/date/locale, 2–4 case IDs, snapshot, common issues (label/supporting case IDs/evidence IDs/differences/unknowns), limitations. C builds it from A's captureCaseSnapshot; A owns `comparisonMarkdown(brief,locale?)` in results/comparison-export. C compares public corpus records, no user private narrative. A history support for comparison briefs can be coordinated without inventing another snapshot model.
9. `ResearchExecution` carries identity/operation/round, real stage durations/models/response IDs/token and tool usage, failure stage, controlledSearch, reserved/actual cost. Null means unknown. No progress events are committed in v1; A shows generic processing, not invented phase counts. B may propose events first if needed; prioritize core safeguards.
