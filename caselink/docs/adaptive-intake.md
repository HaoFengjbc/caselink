# 自由案情整理与分析边界

本说明对应2026-10-09已发布 v3.1 代码（`PROMPT_VERSION=3.1`）。它记录实现与边界；真实模型样本、部署及实际浏览器验证范围见 [verification.md](verification.md)；文末早期记录只代表各自历史批次。

## 两次独立选择，两种模型职责

默认入口 `/new` 依次收集所在地、事项称呼、原始案情、具体诉求与披露边界。使用者可以直接手动核对，也可以展开发送说明后点击“发送并整理”。页面不会因打开、输入或切换步骤自动调用模型。传统九题表单仍可通过 `/new?mode=classic` 使用。

| 环节 | 服务端入口与配置 | 输出与边界 |
|---|---|---|
| 案情整理 | `POST /api/intake`；`OPENAI_INTAKE_MODEL` 默认 `gpt-6-luna` | 读取完整原始描述与已有回答，选择最多12个原话摘录，并生成最多3个针对性事实问题、原因、可选快捷回答及原话依据；服务器分配稳定 ID、过滤不合格问题，英国辖区未知时保留经核查的固定补问。 |
| 当前行动参考 | `POST /api/analyze`；`OPENAI_MODEL` 必须配置，`.env.example` 为 `gpt-6.1-sol` | 先用无工具模型将完整案情整理为公共研究计划，再以规范化地区和抽象争议联网搜索；综合模型结合原始案情、搜索资料与最多3个历史库候选生成比较与行动。无合适比较时最多补充检索一次。 |

两个名称是本项目的配置，不证明特定账户拥有对应模型权限。整理固定低推理强度、4000 token输出上限、默认30秒超时；综合分析默认低推理强度、9000 token输出上限、默认90秒超时；其前置语义规划使用无工具的Sol请求，限时25秒、输出上限3500 token；每轮联网研究使用Sol的`responses.create`和原生`web_search`，发现阶段1000 token和读取阶段3500 token共享65秒、合计最多6次工具调用。首轮未选出相关案例时，预算允许才再搜索一次并重新综合，不再次规划。最终分析共享270秒总预算，Route Handler声明300秒，浏览器等待上限290秒。整理与综合分析使用 OpenAI SDK 的结构化 `responses.parse`，设置 `store:false` 和 `maxRetries:0`。这里不把 `store:false` 表述为供应商绝不保留任何数据。

整理成功后仍须人工核对并确认。第③屏「案情整理」的「确认案情，生成行动参考」是第二次明确提交：点击即确认当前陈述并发起分析，不会把第一次整理等同于已获准生成后续结果。自适应流程不再经过 `/review`；`/review` 只服务传统九题表单，带 `intake` 的会话访问时转回 `/new`。`ANALYSIS_MODE=demo`、手动整理或明确选择规则参考均不调用模型；模型调用失败不会被冒充为实时成功。

## 四屏流程（2026-10-09 合并）

| 屏 | 内容 | 实现要点 |
|---|---|---|
| ① 地区与案件 | 国家或地区、英国辖区、事项类型，新增「这件事和新闻报道或公开表达有关吗」 | 回答存为 `intake.expression`（`yes`/`no`/`unsure`，旧草稿可缺省）。选「有关」可多选表达类型并写入 `background.activities` 供历史库匹配；「无关」提示超出案例库范围，分析时不提供历史库对照（`matches=[]`），整理提示收到 `relatedToJournalismOrExpression`，不再追问新闻或表达话题。 |
| ② 用自己的话说 | 原始描述、诉求、披露边界 | 顶部说明这些文字会在整理或提交分析时发送给 OpenAI；「不想使用 AI？改用逐题问卷」把原话移入 `background.description` 后进入 `/new?mode=classic`。 |
| ③ 案情整理 | 按栏列出 AI 的整理：基本情况、经过（时间线）、对方主张、目前处境、手上材料、最担心、补充回答、目标、公开边界、还缺 | 整理模型对每条原话摘录另写一句简短中性的概括（`summary`）并归入一栏（`slot`：event／claim／status／evidence／concern／other）；红字显示概括，悬停显示对应原话，点击可改写、恢复 AI 概括、改用原话或移除。目标与披露边界按原文显示。黄色虚线是尚未回答的补充问题，点击跳到问题卡。去掉原确认勾选框，提交按钮即确认。分析进行时整理页锁定。 |
| ④ 行动参考 | 结果页 | 默认打开「行动参考」，栏目顺序为 行动参考 → 已核实案例 → 联网补充（待核实）→ 证据与缺口；顶部以目标陈述代替整段原始记录（原始记录折叠可展开），依据分三类标注：已核实（案例库原文）、待核实（联网发现）、AI 整理（需你判断）。 |

等待实时分析时，提交区先列出历史库按同一召回函数（已确认自由案情用 `retrieveNarrativeCandidates`，其余用 `retrieveCases`）找到的最多 3 个已核实候选，档案在新标签页打开，不中断请求；AI 完成后由分析结果决定是否采用。这是前端分段呈现，`/api/analyze` 仍是一次请求。实时模式下两条提交路径都常驻「改用规则参考 · 不联网、不调用 AI」。

## 原始材料、确认与目标

`intake.narrative`保留最多6000字符的原始描述；补充回答、具体目标、披露边界和人工笔记分别保存，不用模型摘要覆盖原文。整理模型只能返回从原始描述或单个回答中连续摘取的原话。服务器拒绝拼接、来源不存在或重复摘录。动态问题必须带有来自原始描述、单个回答、目标或披露说明的连续原话依据；事实摘录仍仅能来自原始描述或回答。问题不允许包含法律结论、法定期限、行动建议、未经核查的网址或联系方式，也不得索取密码、验证码等秘密。服务器按原话、敏感模式及词汇相似度过滤不相关或重复问题；这些检查是有限启发式，不证明语义完全正确。原话检查证明的是“文本中存在”，不是该叙述已独立证实，也不证明摘取的上下文充分。

概括只是阅读辅助：服务器把超过60个汉字（英文160字符）、含9位以上连续数字、触发既有不安全文本规则（建议、法律结论、期限断言、秘密信息、注入）或引入原文没有的敏感话题的概括丢弃，该条退回原话显示；摘录本身仍须逐字出现在原文。缺少概括或栏目的旧输出照常接受，按原话显示在「要点」一栏。

使用者可修改或删除事实笔记。改写笔记与原始摘录分别显示；已确认记录的笔记不能空白，摘录必须仍能回到当前原文。修改原文、回答、目标、公开限制或笔记会撤销确认。服务端拒绝带有未确认 `intake` 的分析请求，全部输入字段参与结果身份校验，旧结果不能自动沿用于新版本。

程序阶段、身份、事项类型、目标和公开意愿不会由整理模型写入固定枚举。已经结案、机构与个人有不同结果、尚无诉讼等情境可以保留在原文中；不能为满足旧表单强行映射成“审前”或“判决后未上诉”。人工确认记录也不等于确认某项法律分类。

填写或修改自由目标 `goalText` 会直接设为 `primaryGoal=other`，清空则设为 `unknown`；不再要求另点按钮把文字提升为主目标。快捷目标折叠为可选项，民事录入不默认展开释放、撤诉等刑事方向。使用者后来明确选择预设时保留该选择，直到再次编辑自由目标；此时原有自由文字是补充诉求。旧草稿中 `unknown + 非空 goalText` 在确认与最终分析时规范为 `other`，服务端仍以原提交输入计算结果身份。真正没有具体目标时才采用需求澄清与材料梳理模板。明确自定义目标的规则参考提供围绕该诉求准备记录的步骤，不冒充已确定当地救济路径。

最终分析提示包含完整原始记录、补充回答、具体诉求与披露边界，人工笔记也标为用户提供资料，不当作独立证据。传统结构化字段仍用于确定性匹配和部分适用性检查；自由叙述不会自动把“律师”“职业记者”“上诉”等词映射成经过核实的结构化事实。手动规则参考因此较保守，不能等同于已对自由叙述作完整法律理解。

对于已确认的自由案情，如果原文已说明委托律师，但旧资源选项尚未确认，服务器不会据此认定没有律师。涉及律师判断且原本列为优先的行动会保守降为“有条件”，补充核实本地律师受托事项、职责和当前程序范围的前提与说明，原始叙述及资源选项保持不变。旧表单路径、明确选择无资源的输入及其他程序阶段和证据校验仍保留原有限制；未知目标仍使用固定澄清模板。

## 披露与会话数据

向配置的 OpenAI 服务提交案情，与向媒体、组织或公众披露案情，是两个不同操作。整理前的发送说明列出所在地、原始描述、目标、披露边界与补充回答；最终确认页另行说明分析请求。产品本身不发送倡导邮件、公开材料或向机构递交案件。

`disclosureDetails` 或 `disclosure-details` 补充回答只要存在非空文本，服务器就按需要人工核对的具体边界处理，不能被总体“可公开”选项覆盖。标为涉及公开传播的行动只能暂缓，规则识别到直接公开姓名、发布案情或联系媒体的执行步骤也会拒绝；服务器补充逐项确认内容、接收人、渠道和同意范围的条件与限制。这个保守规则不声称已理解所有自由文本，甚至“允许部分公开”的文本也需要逐项确认；它不会擅自把用户的公开意愿枚举改成另一项。

原始草稿与分析结果使用浏览器 `sessionStorage`，不可用时在页面进程内存中继续；没有跨设备、跨用户的案情库或共享分析缓存。自适应视图缓存中的输入身份包含完整字段，不是脱敏哈希。清空会话会删除 `caselink.session.v1`、`caselink.adaptive.view.v1`，并清理已注册的内存视图。案情不进入URL。

动态问题使用服务器生成的 `dynamic-<20位十六进制>` ID；旧的固定问题 ID 继续兼容。问题原文、可选的依据摘录及最多40条回答均可会话恢复；再次整理不删除已有回答，也不覆盖人工改写的事实笔记。空白回答不视为已回答，明确“不清楚”也是一个回答。

两个 POST 请求体上限均为512 KiB；同源POST核对JSON内容类型，响应使用 `no-store`。前端同步锁防止同一次提交的双击并发，取消、输入变更或离开页面会隔离晚到结果。没有服务端共享幂等缓存或全局限流；`requestId`只用于关联请求，不能承诺跨请求只收费一次，取消也不保证已开始的上游请求不计费。

## 英国辖区与资料范围

目前只核查英国存在英格兰及威尔士、苏格兰、北爱尔兰三个不同法系，用于在“英国”而具体地区未知时追问地点。依据是英国法院及审裁处司法机构的 [The justice system and the constitution](https://www.judiciary.uk/about-the-judiciary/our-justice-system/jud-acc-ind/justice-sys-and-constitution/)，本轮只读核查日期2026-10-08。该页面不支持个案适用法律、程序、期限或胜诉判断；这一固定补问本身没有进行英国个案法律检索；最终联网研究是另一次由使用者明确触发的操作。

当前正式运行时语料版本为`2026-10-08.v2`，含21份独立来源、22条案件记录、14个地区和187条引文。已确认自由案情的实时分析按结构化字段及叙述关键词召回最多3个候选；无命中信号时可为0，模型也允许全部排除。关键词不是已确认案情，候选不是已确认匹配。最终采用案例的历史行动表由静态资料装配，来源仅保留采用案例和行动实际引用所需的证据。原报告中的部分结果、未决状态、日期冲突、作者评价和建议不能改成确定的终局事实。

新增本地目录原有26个文件（24个PDF、2个sources.json），去重后21份独立来源、804个物理页，包括20份CFJ PDF及1份ABA网页打印件。首批3份报告保留，18份新增文档已整理为19条新增案件记录：Pakistan专题提取两案共享来源，Omar Radi同人两起程序分别记录。`data/research/`保留盘点、提取与审阅工作材料；只有经过审阅并合并至正式JSON的记录进入运行时，原始PDF、报告全文与渲染页图不进入`public/`或模型上下文。完整清单与限制见 [new-corpus-inventory.md](new-corpus-inventory.md)。核查选定引文及必要上下文，不等于804页完整精读或独立事件调查。

v3 实时路径以联网`web_search`为主、正式库补充。完整案情会发送给无搜索工具的语义规划和综合分析；公开搜索接收规划后的争议关系、所述损害、诉求及证据问题等抽象内容，不局限于固定标签。隐私筛查会拒绝常见标识和长段原文，但不能保证完全匿名。详见[联网研究说明](web-research.md)。资料取得与案例相关性分开记录，`actionOrigins` 逐项区分 AI、规则及预置来源；`live_ai` 不表示每项行动都是模型生成或一定找到相关案例。

| 情境 | 需要保留的差异 | 本地独立测试覆盖 |
|---|---|---|
| Dian Abdullah 博客案 | 已交保与审理继续可以并存；博主不自动变成记者，过去保释不证明今天的拘押状态。 | 原始叙述和“核对庭审材料”的自定义测试目标保留；不自动指定程序或身份。 |

| Moses Bwayo 纪录片案 | 保释与后来因检方未举证撤案是分开的事件；不推断因果，也不强迫结案情境进入旧阶段枚举。 | 结案记录与后续问题的测试目标保留；阶段允许未知。 |
| Malaysiakini 与 Steven Gan | 第三方评论、机构被定罪与编辑无罪需分别归属；机构不能自动套成人员身份或拘押字段。 | 分离主体的原始描述和目标保留；用户自述结果与历史库的结果需按各自主体及来源区分。 |

用户新案的结果描述与正式历史库分别检查。对终局结果的一般拒绝规则仅允许狭窄例外：输出明确归属“根据你的描述”，原始叙述或回答中存在同一主体与同一结果的连续表述，且该句不涉及正式历史库的案件姓名。该例外不把用户自述变成经过核实的事实，也不能用编辑的结果替换机构的结果。

独立回归文件为 `tests/adaptive-independent.test.ts`，包含9项：四种语境的原文、目标和未知阶段保留；零采用候选不污染来源；两个自由披露入口均不能被总体公开覆盖；新案结果归属；两项会话存储同时清空。其他覆盖位于 `tests/intake.test.ts`、`tests/adaptive-intake.test.ts`、`tests/adaptive-analysis.test.ts`。这里的模型响应均为本地mock；测试不证明真实模型永远遵守语义边界。API schema、引用归属与确定性约束不能替代人工核查全文含义。生产构建、部署和真实模型调用由本轮验收记录另行记载，本文件不宣称这些步骤已经通过。

首轮自由案情版本于2026-10-08独立复跑：`vitest run tests/adaptive-independent.test.ts` 为9/9通过，`tsc --noEmit`通过。执行使用本机项目配套Node运行时，没有调用付费模型、运行构建或部署。
