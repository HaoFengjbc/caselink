# CaseLink 架构

本说明对应2026-10-09已发布 v3.1 实现（`PROMPT_VERSION=3.1`）；本轮真实模型样本、执行边界与部署状态见 [verification.md](verification.md)。CaseLink 是单个 Next.js App Router 应用：中英文问卷与结果界面、同源服务端 API、版本化静态证据库和 OpenAI 原生网页搜索。Python只用于开发阶段离线提取；网站没有数据库、向量库、自建运行时爬虫或Python服务。

## 数据边界

`src/lib/contracts.ts` 是公共 TypeScript / Zod 契约入口。它定义新案输入、精度明确的日期、案件、事件、行动、结果、报告建议、原文证据、源文档、当前机构资源、模型输出及服务器装配结果，并引入 `src/lib/intake/contracts.ts` 的自由案情、原话摘录、补充问题和确认记录契约。

运行时证据由 `src/lib/corpus.ts` 读取并验证，演示输入另行加载：

- `data/cases/cases.json`：当前22条案件记录，事件／行动／结果分开保存；同人不同程序分别归属。
- `data/evidence/evidence.json`：有案件与文档归属的英文短摘录、中文解释和物理／印刷页码。
- `data/evidence/documents.json`：报告作者、发布日期、SHA-256、页数、官方链接、事实截至时间与本次核查日期。
- `data/resources/resources.json`：当前已核实的官方机制或协助入口及适用范围。它与历史参与者分开。
- `data/demo/fixtures.ts`：两个明确虚构的新案输入，不进入历史案例数。

所有事实性历史表格从静态JSON渲染；模型不负责重写原文、页码、来源链接或报告日期。报告建议独立于已实施行动，部分变化、未决与未记载是独立结果类型。案例详情始终保留报告时点，不显示为今天的状态。

## 页面流

首页 `/` → 自由案情流程 `/new`（地区与事项类型、原始描述与目标、可选 AI 整理及人工核对）→ 确认 `/review` → 结果 `/analysis`。旧九题结构化表单保留在 `/new?mode=classic`；它不再是默认入口。

AI 整理与最终分析分别由使用者明确触发。整理读取完整叙述与已有回答，提取原话并生成最多3个有原话依据的动态事实问题；服务器分配稳定 ID，保留英国辖区固定补问及旧问题 ID 兼容。记录最多40条回答，重整不删除已有回答或人工笔记。模型不能代选公开意愿或程序阶段。填写自由目标直接设为自定义主目标，清空恢复未知；用户明确选用快捷目标后尊重其选择，直至再编辑自由目标。旧的 `unknown + 非空 goalText` 在确认和分析入口规范化。使用者核对后才能把带 `intake` 的记录交给分析；修改后撤销确认，旧结果过期。完整边界见 [adaptive-intake.md](adaptive-intake.md)。

历史资料入口 `/cases` 可按国家、身份和材料标签筛选，`/cases/[id]` 展示事件、行动、已知结果、建议、冲突与证据。原文入口指向与用户PDF哈希一致的官方报告，不在项目`public`再分发全文。

`src/lib/session/index.ts`使用`caselink.session.v1`保存版本化草稿、题目位置及最后结果；`caselink.adaptive.view.v1`保存自适应流程页面与整理结果。浏览器存储不可用时回退页面进程内存。保存结果时核对完整输入的本地键，防止已修改草稿被旧结果覆盖。这个本地键包含原始字段，不是脱敏摘要；清空会话会删除两项存储并清理已注册的内存视图。输入与最后一次有效结果通过浏览器会话状态恢复；没有跨设备／跨用户历史功能，也没有服务端共享案情或分析缓存。修改案情与生成新结果是两步，过期结果不能冒充新建议。案情不放入URL。

## 界面语言

界面支持中文（默认）与英文。语言保存在 `caselink-locale` Cookie，根布局在服务端读取，因此页面按请求渲染。界面字符串在 `src/lib/i18n/`；历史资料的英文译文在 `data/i18n/en.json`，按 ID 覆盖显示，不改动经过核对的中文原始数据。分析请求可带 `locale`，规则引擎、预置示例与实时 AI 按该语言输出；未带时与原来完全一致。

## 检索

`src/lib/retrieval/match.ts` 使用启发式维度：国家或地区、明确身份、表达活动、历史介入阶段和具体困难。当前权重为2／1／2／1／2，保留逐维度理由和差异，**不是经验证的概率**。排序不读取历史结果好坏。

未知项不加分，单独阶段相同不足以形成相关案例。阶段取历史行动的 `stageAtAction` 或事件的 `stageAtEvent`，不拿旧案报告结束时的状态替代。跨地区、跨身份和多年资料差异必须保留。

实时分析以网页研究为主。正式库补充从22条案件记录中按结构化字段与叙述关键词召回最多3个候选，无命中信号可为0；候选不代表已确认匹配，关键词不是已证实新案事实，模型可全部排除。匹配标签与维度仍由服务器固定。历史行动表和补充来源仅由最终采用案例装配，行动明确引用的证据另行保留。当前正式语料为 `2026-10-08.v2`，21份来源、14个地区、187条引文；`data/research/`工作材料只有经过审阅并合并至正式 JSON 的记录才进入运行时。

## 生成与责任分工

服务端验证输入并读取经过选定引文核查的语料，研究后生成解释与行动参考。`ModelAnalysisOutput`包含库内可比性解释、最多3项行动、信息缺口及限制；`WebModelAnalysisOutput`增加网页比较及行动网页引用。模式、输入哈希、版本、时间、研究状态、行动来源和源证据由服务端装配，不能由模型自报。

`src/lib/ai/hash.ts` 对规范化对象全部字段做SHA-256，避免只比较部分字段而漏掉影响行动的目标、既往行动或公开限制。`src/lib/ai/errors.ts` 使用带`code`的中文错误；无效输出、拒绝、限流、取消和超时不表示分析成功。

实际编排入口是 `src/lib/ai/service.ts`。v3.1 的实时链路为：

1. `research/planner.ts` 用无工具 Sol 请求理解完整原始案情、已确认笔记、回答和目标，生成公共研究计划，最多25秒。`research/plan.ts`核对支持原话、常见标识、长原文片段和明确矛盾；私有标识列表及核对摘录不作为可枚举字段传给网页搜索或客户端。
2. `research/query.ts`用规范化地区和抽象关系、争议行为、损害、诉求及证据问题构造查询；不再只依赖固定议题标签。`research/provider.ts`把每轮原生 `web_search`研究分为两个请求：发现阶段最多3次工具调用、1000 token，挑选最多3个实际来源 URL；读取阶段再以 `open_page` 打开候选，最多3次工具调用、3500 token。两阶段共享单轮65秒截止时间，工具调用合计≤6，不因开始读取而重新获得65秒。规划失败或不能安全形成有意义的计划时不启动搜索，也不回退到原文关键词挖掘。
3. `ai/adapter.ts`用无工具 `responses.parse` 综合完整案情、研究资料和最多3个正式库候选；默认90秒，允许配置1—90秒，输出预算默认9000 token。
4. 首轮完成但综合结果没有采用合适网页案例，或搜索没有可用引用时，剩余预算至少95秒才补充检索一次。复用已校验计划，改用关系、救济诉求、因果或证据角度，再执行一轮发现与读取；不再次调用规划器。第二轮成功后报告与分析整体替换；第二轮失败则保留此前有效的报告和分析配对，不混用两轮同名引用 ID。

最终网页报告仅装配读取阶段的段落；发现摘要不进入正式报告，即使发现时已打开候选页面也不能绕过独立读取。每条正式引用须对应选定 URL，并匹配读取阶段 `completed open_page`。同时依赖已读与未读引用的混合段落整段丢弃。`citationKind`继续区分原生 `url_annotation` 与精确匹配工具返回 URL 的 `tool_returned_link` 窄回退，二者均受读取条件约束。相同页面明确记载一、二审时允许分阶段重复引用；不能把未知精确日期写成整个后续程序未知。来源的 `pageOpened=true`只记录完成打开步骤，不证明全文可用、语义理解准确、所有程序提取完整或逐句事实核实。

整个分析共享270秒截止时间，`/api/analyze`声明 `maxDuration=300`，浏览器等待290秒；各阶段都受剩余总预算限制。取消会停止后续编排并隔离晚到响应。SDK自动重试关闭（`maxRetries:0`）；最多一次补充研究是应用显式编排，不是 SDK 重试。使用 `store:false`，但不将其解释为供应商绝不保留数据。模型配置为 `gpt-6.1-sol`，规划与搜索固定低推理强度，综合分析默认低推理强度。拒绝、截断、解析失败或校验失败不装配该轮成功结果；第二轮失败保留首轮结果时会明确披露。实际部署时限仍受账户与平台约束。

案情整理入口为 `src/lib/intake/service.ts`，单独使用 `OPENAI_INTAKE_MODEL`（代码默认 `gpt-6-luna`）、固定 `reasoning.effort=low`、4000 token 输出上限与默认30秒时限，服务端允许1—30秒，Route Handler的 `maxDuration=40`。整理同样使用 `responses.parse`、`store:false`、`maxRetries:0`。`.env.example` 的分析模型为 `gpt-6.1-sol`；分析配置没有模型缺省回退，必须显式设置 `OPENAI_MODEL`。这些是本项目配置值，不代表任一账户的模型可用性已经验证。

API边界如下：

| 入口 | 行为 |
|---|---|
| `POST /api/intake` | 严格校验`{input, locale, forceManual?}`；提取原话并提出最多3个动态事实问题；固定英国辖区补问保留，手动模式不调用模型 |
| `POST /api/analyze` | 严格校验`{input, requestId, forceRule?, locale?}`；服务端自行取语料与模型配置，`forceRule`仅明确选择规则参考 |
| `GET /api/capabilities` | 仅返回模式和配置可用性；兼容字段`accessRequired`固定为false，不返回密钥或模型配置内容 |

两个 POST 的请求体上限均为512 KiB（524288字节）；POST核对同源与JSON内容类型。响应使用`Cache-Control: no-store`，错误包含`code/message/requestId`。2026-10-08按用户要求取消站内访问密码及授权Cookie，规则参考仍可单独使用。前端防止并发重复点击并隔离取消后的晚到结果，但 `requestId` 不是服务端幂等键；没有跨实例去重或全局限流，取消不保证已启动的上游请求不计费。

三种结果必须分别标注：

| 模式 | 含义 |
|---|---|
| `preset_demo` | 与固定虚构输入完整哈希相对应的确定性预置演示；没有实时模型调用 |
| `rule_reference` | 根据当前输入作规则检索与参考；没有实时模型调用 |
| `live_ai` | 完成服务端综合模型请求并通过校验；不代表网页研究一定完成、一定找到相关案例或每项行动都由模型生成 |

`actionOrigins`逐项标记 `ai`、`rule` 或 `preset`。未知目标被确定性模板替换时，即使整体为 `live_ai`，对应行动仍标为 `rule`。`webResearch.status`只说明资料获取情况；`researchAssessment`另列案例相关性、尝试次数和补充研究结果。成功取得带引用的网页不等于找到相关案例，更不等于资料已经独立核实。

`data/demo/presets.ts`将两个固定示例输入哈希映射到以同一证据规则生成的确定性结果。保留exampleId但编辑了内容不会命中预置。`ANALYSIS_MODE=demo`不调用模型。实时模式缺少配置或首轮综合模型失败必须明确报错，不能悄悄转成预置演示并保留实时成功标记；规划、搜索及第二轮失败按上述降级边界如实显示。

`src/lib/evidence/validate.ts` 核对证据是否属于本次上下文、案件与源文件、页码范围、报告建议／已实施行动的来源类型，并检查重复案例、错误目标、未经提供的资源、明显不支持的终局结论、数值概率和未核实联系方式。规划与问题筛查也使用有限的原话和模式检查，不能保证完全匿名、消除提示注入或证明语义正确。确定性检查不是完整的自然语言蕴含验证；有引用ID不代表每个叙述细节都被证明，使用者仍须看原文与差异。

公开限制不只是提示词：私下处理、待征求意见或不清楚时，涉及传播的选项只能条件性或暂缓。存在非空具体披露说明或相应补充回答时，即使总体选择“可公开”，标为涉及公开传播的行动仍须暂缓并逐项核对内容、接收对象、渠道和同意范围；规则识别到直接公开的执行步骤也会拒绝。需要律师执行的程序动作必须说明法律支持前提。历史参与机构不等于当前承诺受理；模型只能引用已提供的资源ID。

## 核查与部署边界

离线脚本`extract_pdfs.py`执行哈希去重和逐页提取；`check_evidence.py`比对源文件身份、摘录位置及归属。`scripts/data.test.ts`验证静态数据契约和关键历史边界。详情见[data-notes.md](data-notes.md)。

实时配置在`src/lib/ai/config.ts`读取。`ANALYSIS_MODE=live`要求服务端API密钥和模型；配置完整即可直接调用。站内密码、签名Cookie和`/api/access`已移除。现有同源检查、请求体限制、无缓存及证据校验继续适用；未实现全局限流。

安装使用npm锁文件。应用按普通Next.js项目部署；API密钥仅放服务端环境变量。新分析不写入服务器本地JSON来模拟持久化。静态历史库更新须重新构建发布。界面、检索和模型适配分离，未来可替换持久化与检索实现，但本版不声称具有真实高风险个案管理平台的安全能力。

实际测试、生产构建、实时调用与部署是否已执行，以根README及验收记录为准；本文件不将接口代码存在等同于真实模型已被调用或已部署。
